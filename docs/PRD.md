# 智备课 MVP PRD

## 1. 背景与目标

现有 `ai-lesson-planner` 已定义来源、反向设计、质量门禁和审核协议，但仍主要由 Agent 通过文件和 Prompt 操作。MVP 将其产品化为教师可直接使用的 Web 工作台。

目标：让教师通过结构化输入，在 3 分钟内获得可追溯、可审校、可导出的单节课初稿。

## 2. 用户角色

- **教师**：创建课程简报、补充学情与来源、修改并提交审核。
- **教研员**：检查学科事实、课标、目标与评价，批准或退回。
- **课程管理员（后续）**：维护模板、标准库、模型与成本策略。

## 3. 核心流程

```text
课程简报 → 来源与学情 → 结构化生成 → 自动质量门禁
→ 教师审核 → 教研审核 → 导出/发布（MVP 不自动发布）
```

## 4. MVP 范围

### P0

- 课程主题、年级、学科、时长、授课方式、学习结果、学情、难点与来源输入；
- 7 阶段课堂流程与分钟分配；
- 3 个可观察目标及成功标准；
- 目标—活动—评价完整映射；
- 8 维质量评分与 `SOURCE_GAP` 硬门禁；
- AI 草稿、教师审核、教研审核状态流转；
- 本地草稿箱；
- Markdown 与 JSON 导出；
- 响应式 Web。

### 暂不做

- 用户账号、组织权限与云端数据库；
- 文件 OCR、教材版权库与真实课标检索；
- LMS/钉钉/飞书自动发布；
- 班级与学生个人数据；
- 批量课程与多人实时协作；
- 未配置模型服务时宣称使用大模型生成。

## 5. 关键规则

1. `topic / subject / grade / duration / learningResult` 必填。
2. 时长为 20–180 分钟整数，课堂环节分钟数总和必须等于总时长。
3. 没有来源时课程包仍可作为探索草稿，但质量门禁必须失败。
4. 所有目标必须至少被一个活动和一个评价覆盖。
5. 课程包初始状态只能为 `draft_ai`。
6. 通过质量门禁后才能提交教师审核。
7. 任何状态变化记录更新时间；MVP 在浏览器本地保存。

## 6. 验收标准

- 缺少必填字段时显示可操作错误信息，不发起生成请求。
- 示例数据可完成从生成到审核流转。
- 无来源生成结果显示硬失败并阻止提交审核。
- 生成 JSON 通过仓库结构约束；目标、活动、评价引用有效。
- 45 分钟课程各环节之和等于 45。
- 导出的 Markdown 可读，JSON 可被重新解析。
- 375px 与 1440px 宽度下核心流程可用。

## 7. 风险

- **事实风险**：MVP 不负责检索与核验事实，只登记来源并提示人工审核。
- **模型误导**：当前线上默认展示“可审计演示引擎”；接入真实模型前不冒充大模型输出。
- **隐私风险**：界面明确禁止输入学生个人信息；服务端不做持久化。
- **版权风险**：来源材料默认仅用于本次备课，不对外公开。
